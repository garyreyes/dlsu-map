# Splitting the Work

How two people build `docs/ROADMAP.md` in parallel without waiting on each other or editing the same files. Written
and agreed 2026-10-19.

## The two lanes

| Lane | Owns | Who | Why |
|---|---|---|---|
| **A: what the student sees** | Platform (scaffold, CI, hosting, offline), every screen, the 3D scene, the indoor view | Gary | Owns the repo and the Cloudflare account, which the platform work needs |
| **B: what the app knows** | Campus data, room lists, the room-code parser, routing, the floor pipeline, data rollout, on-site checks | Charles | Has campus access and the STRC photos; the data work happens on campus |

Lane A has 20 roadmap items, Lane B 17, but Lane B also carries the photography and on-site time, so the load is
about even. Each sub-phase's lane is in the **Lane** column of `docs/ROADMAP.md`.

## Where the lanes meet

Each lane can work ahead of the other by agreeing these shapes first. Until the real one lands, Lane A builds
against a small hand-written sample in the agreed shape, so it never waits.

| Meeting point | Lane B delivers | Lane A uses it in | Agree the shape before |
|---|---|---|---|
| **Campus data** | `campus.json` + buildings (2b) | the scene (2c) | 2a starts |
| **Room codes** | `parseRoomCode()` (3a) + `rooms.json` (3b) | search and room card (3c, 3d) | 3a starts |
| **Routes** | `route(from, to, mode)` returning steps (4b, 4c) | route preview, steps list, player (5b–5d) | 4b starts |
| **Floor files** | `buildings/<slug>.json`, floors in meters + `checked` (6b, 6d; shape in `shared/data/indoor.ts`) | floor builder and indoor view (6c, 7a) | 6a starts |

Agree a shape by writing the TypeScript types (and a sample file) into `src/shared/data/` in one small PR that both
of you look at.

## Working rules

- **One branch per sub-phase**, named after its roadmap ID: `1a-scaffold`, `3a-room-code-parser`.
- **Every change goes through a pull request.** `main` is protected: `gates` must pass and the branch must be up to
  date with `main`. If GitHub says the branch is out of date, press **Update branch** (or merge `main` into it) and
  let `gates` run again.
- **Look at each other's PRs** before merging, even though GitHub doesn't require an approval (D22). A quick read
  catches a broken meeting point early.
- **Mark the roadmap in the same PR:** set the sub-phase to `done` in `docs/ROADMAP.md` and add the
  `docs/CHANGES.md` entry. Set it to `in progress` when you start, so the other person can see it.
- **Dependencies go in their own small PR** (one `package.json` change at a time), so two branches don't fight over
  the lockfile.
- **Claude Code:** start each session by naming the sub-phase ("let's do 3a"). It reads `CLAUDE.md`, the roadmap and
  this file, then runs `feature-planner` for that sub-phase only.
- **When you're blocked by the other lane,** build against a sample in the agreed shape and keep going. Don't wait.
